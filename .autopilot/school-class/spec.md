# Спецификация: Школьный класс

## Задача и решение
Учитель ведёт общее пространство класса, ученики и родители видят актуальные задания и расписание. Ученики отмечают выполнение, получают достижения, учитель награждает за качество. Русскоязычная веб-версия и устанавливаемые iOS/Android приложения используют один сервер и реальные аккаунты. Интерфейс адаптивный: удобная навигация на телефоне, просторный кабинет на компьютере. Рабочее название «Классно» — заменяемый текст, не предоставленный пользователем бренд.

## Подтверждённые решения брифинга
Пользователь выбрал веб + приложение, реальные аккаунты. На предложение «Учитель и родители: email и пароль. Ученики: логины, которые создаёт учитель — без обязательной почты. Родители: персональное приглашение к своему ребёнку» ответил «Подходит».

## Реализация
React + TypeScript + Vite, CSS, lucide-react; Capacitor 8 для нативных контейнеров с тем же интерфейсом. Node >=22.13, Express, SQLite через node:sqlite, scrypt для паролей. Один сервер и база для веба и приложений. Без обязательного платного облачного аккаунта. Первое развёртывание — один экземпляр сервера с постоянным томом. Dockerfile и инструкция production запуска, HTTPS на reverse proxy. Локально всё работает с настоящими аккаунтами без внешних сервисов. Публичный домен и размещение выбираются отдельно: это не блокирует реализацию и локальную проверку.

Анкета минимальная и расширяемая: ФИО, необязательная дата рождения, имя/телефон/email родителя, приватная заметка. Адреса и медицинские данные не собираем, поскольку не запрошены. Временные пароли задаются учителем, хранятся только хеши; приглашения — криптографические токены с истечением и одноразовым потреблением. Нет публичных рейтингов детей. Достижения за количество различных выполнений, без выдуманных оценок успеваемости.

Веб: HttpOnly session cookie, SameSite и проверка Origin на изменяющих запросах. Мобильные клиенты: session bearer только в памяти (повторный вход после закрытия), без localStorage токенов; сохранение входа в keychain можно добавить позднее. Это безопасная минимальная реализация без неподтверждённого плагина secure storage. Сессии хешируются в БД, имеют срок, отзываются при выходе/смене пароля. CORS — точные разрешённые origins (локальные адреса + capacitor://localhost/http://localhost), в production только настроенные. Валидация длины/типов/дат, параметризованный SQL. Все выборки проверяют роль и принадлежность класса/ребёнка; приватные поля сериализуются по роли. Ограничение auth запросов.

Главный шов тестов — HTTP API настоящего приложения с временной SQLite базой через node:test + supertest. Проверять полные сценарии и запрещённый доступ: две независимые семьи/класса, вход/выход, принятие приглашения, анкеты, ДЗ, повторные награды. UI проверяется сборкой TypeScript/Vite и браузером на desktop/mobile. Не мокать собственную бизнес-логику.

## Вне текущей поставки / внешние условия
Публикация в App Store/Google Play и публичное развёртывание не запрошены отдельным действием и требуют аккаунтов/домена/сервера. Проекты и инструкции поставляются; нельзя заявлять публикацию или установку на телефон без проверки. Android build требует JDK/SDK, iOS simulator — runtime. Email-подтверждение и SMTP восстановление не имитируются: предусмотреть операторскую команду одноразового сброса пароля (токен локально), описать как администратор передаёт ссылку владельцу. SMS, чат, оценки, загрузка файлов и push не входят в исходный бриф.

## Обнаруженное ограничение D01 (T04)
iOS SDK присутствует, но компиляция требует отсутствующий системный CoreSimulator.framework. checkFirstLaunchStatus exit69. Штатный runFirstLaunch устанавливает компоненты и принимает лицензию; требуется действие владельца Mac. Исходный проект поставлен, iOS бинарник остаётся незакрытым требованием. Android debug APK успешно собран для явно локальной проверки, native runtime не проверен; публичный HTTPS origin для релиза ещё не выбран.
