## Из брифа
«мобильное приложение для школы»; «веб версию и приложение, с реалными аккаунтами»; «список учеников и их анкетные данные, расписание уроков, звонков»; «домашние задания»; «получать ачивки, баджи»; «Учитель тоже может выдавать награды».

## Разделы спецификации
Истории и приёмка (указанные требования), Реализация, Границы и швы.

## Что должно заработать и критерии приёмки
Реализуй ДЗ + выполнение + награды end-to-end. Учитель CRUD ДЗ с subject/title/description/dueDate, список выполнения по ученикам. Ученик меняет только свою отметку; родитель read-only с выбором своего ребёнка. Автобейджи 1,5,10 разных выполненных заданий с уникальным award key в транзакции, earned badges сохраняются при снятии отметки, снять/поставить не дублирует достижения. Учитель выдаёт за выполненное ДЗ одну ручную награду student+homework с текстом похвалы; дубликат идемпотентен. Отдельная страница «Награды»: коллекция, описание условий и прогресс ученика; учитель может просматривать по ученикам. UI красивые карточки заданий со сроком/статусом, фильтры открытые/выполненные, формы и детали, ошибки, пустые состояния. Без публичного рейтинга. API tests через общий createApp: cross-class/role/student authorization, повторные completion/award запросы, count threshold и parent-read-only, invalid date/fields. Не менять shared/schema, только свою зону; при необходимости сообщи. Критерии: CRUD ДЗ; разные роли видят только свои данные; отметки сохраняются; teacher completion overview; автоматические и ручные награды без дублей; в UI все действия работают; npm test/build. Читать core-contract.md.
