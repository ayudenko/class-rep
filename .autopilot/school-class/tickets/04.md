## Что должно заработать и критерии приёмки
Подготовь реальную поставку web+Capacitor iOS/Android: добавь native проекты, production web build+cap sync, настрой API URL для мобильной сборки через VITE_API_URL и сессии в памяти из core. Никаких development server URL в release. Иконки простые векторные/code native, мобильные safe areas. README по-русски с точными командами dev/build/test, первым teacher account, приглашением parent, student login, recovery, локальным и production запуском (один сервер+persist SQLite), env.example без секретов, Dockerfile и .dockerignore. Browser runtime API same-origin; mobile требует HTTPS доступного API. Проверить CORS и production static serving. Изучить доступные Xcode simulator/JDK/SDK; iOS simulator build если возможен, Android если SDK доступен. Не устанавливать тяжёлый Android Studio/SDK без необходимости; сообщить отсутствующую среду честно, нельзя считать mobile бинарники готовыми без сборки. Внимательно проверить интеграцию frontend/core/schedule/homework и исправить реальные несовместимости с тестами. Критерии: production web сервер отдаёт приложение, реальные аккаунты/API работают; мобильные проекты созданы/синхронизированы; доступный native build проверен; README воспроизводим; npm test/build зелёные; ограничения релизной подписи/публикации перечислены. Не публиковать сайт/магазины. Можно менять интеграционные общие файлы, но не .autopilot. Это полноценная поставка, а не только конфиг.

Требование приложения считается полностью закрытым только при успешной native сборке. Если среда/подпись не позволяет — вернуть REQUIREMENTS R01/G01 partial с точной причиной, не маскировать наличием конфигов.
