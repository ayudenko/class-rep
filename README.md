# Классно

Русскоязычное пространство школьного класса: реальные аккаунты учителя, учеников и родителей, анкеты, расписание, домашние задания и награды. React/TypeScript + Node/Express + SQLite, iOS и Android на Capacitor 8. Название рабочее.

Исходный код: [GitHub — ayudenko/class-rep](https://github.com/ayudenko/class-rep).

## Локальный запуск

Нужен Node.js >=22.13 и npm.

```sh
npm ci
npm run dev
```

Откройте http://localhost:5173 (именно localhost). API слушает 127.0.0.1:3000. База создаётся в `data/klassno.sqlite`. Демоаккаунтов нет. Создайте аккаунт учителя, затем класс и ученика. Передайте ученику его логин и начальный пароль лично; смена пароля находится в профиле. Для родителя создайте приглашение в анкете, передайте ссылку лично. Родитель открывает ссылку, регистрируется или входит, затем принимает приглашение. Ссылка действует 48 часов и используется один раз. У родителя может быть несколько детей.

```sh
npm test
npm run build
npm start
```

После сборки `npm start` отдаёт интерфейс и API на http://localhost:3000. Без NODE_ENV=production это локальный режим с cookie без Secure. При закрытии native приложения потребуется повторный вход: bearer хранится только в памяти.

## Порядок уроков и звонки

Новый урок автоматически добавляется в конец выбранного дня: вводить его номер не требуется. Учитель меняет порядок уроков своего класса; ученики и родители видят сохранённое расписание. В одном дне может быть не больше 20 уроков. После удаления номера уплотняются, а при переносе в другой день урок добавляется в его конец.

Звонки задаются отдельно для номеров уроков. Время относится к месту в расписании: после перестановки предмет получает время нового места, сами звонки сохраняются. Например, если математика перемещена с первого места на второе, для неё отображается время второго звонка.

Порядок сохраняется сервером целиком для выбранного дня. Если состав дня успел измениться, сервер отклоняет устаревшую перестановку: обновите расписание и повторите действие. Обновление не требует миграции базы; идентификаторы уроков сохраняются.

## Один production-сервер

Приложение развёрнуто на [Fly.io](https://klassno-school-ayudenko.fly.dev); конфигурация и обслуживание описаны ниже. Для самостоятельного размещения нужны домен, HTTPS reverse proxy и постоянный том для базы. Публикация в магазинах не выполнялась. Веб использует API того же origin, поэтому **при веб-сборке оставьте VITE_API_URL пустым**. Не используйте native dist для веб-развёртывания.

```sh
docker build -t klassno .
docker volume create klassno-data
docker run -d --name klassno --restart unless-stopped \
  -p 127.0.0.1:3000:3000 -v klassno-data:/data \
  -e ALLOWED_ORIGINS='https://YOUR-DOMAIN,capacitor://localhost,http://localhost' \
  -e PUBLIC_URL='https://YOUR-DOMAIN' klassno
```

Замените YOUR-DOMAIN реальным доменом. Reverse proxy должен завершать TLS и перенаправлять на 127.0.0.1:3000. Production cookie имеет Secure/HttpOnly/SameSite=Lax. ALLOWED_ORIGINS — список точных origins без завершающего `/`, wildcard не используется; если список не задан, изменяющие запросы отклоняются. Native origins нужны для токена в памяти. Не публикуйте порт базы, не запускайте несколько серверов на одной SQLite базе. Для резервной копии остановите контейнер и сохраните весь том; восстановление делайте при остановленном сервере. Проверьте регистрацию/вход через HTTPS до выдачи доступа.

`.env.example` описывает переменные. `npm start` сам `.env` не читает: экспортируйте значения или выполните `node --env-file=.env server/index.mjs`. Не копируйте шаблон production настроек в локальный запуск без изменения значений.

## Восстановление доступа

Администратор сначала проверяет личность владельца вне приложения, затем на сервере выполняет:

```sh
DB_PATH=/path/to/klassno.sqlite PUBLIC_URL=https://YOUR-DOMAIN npm run reset-password -- USER_LOGIN
# В контейнере:
docker exec -it klassno npm run reset-password -- USER_LOGIN
```

Команда выводит секретную одноразовую ссылку (1 час). Передайте её владельцу лично, не сохраняйте в общих логах/чатах. После сброса все сессии отзываются. Отправка email не имитируется, SMTP не требуется.

## Развёртывание на Fly.io

`fly.toml` настроен для `klassno-school-ayudenko`, региона Frankfurt (`fra`), одной Machine `shared-cpu-1x` с 512 MB RAM и тома `klassno_data` размером 1 GB. Приложение развёрнуто по адресу https://klassno-school-ayudenko.fly.dev; remote Docker build и `flyctl deploy` завершились успешно. Веб-сборка использует same-origin API; секреты и тестовая база не входят в Docker build context.

Для первого развёртывания в авторизованном аккаунте (уже существующие приложение/том повторно не создавайте):

```sh
flyctl apps create klassno-school-ayudenko --org personal
flyctl volumes create klassno_data --app klassno-school-ayudenko --region fra --size 1
flyctl config validate
flyctl deploy --remote-only --ha=false
flyctl status
flyctl checks list
curl --fail https://klassno-school-ayudenko.fly.dev/api/health
```

Флаг `--ha=false` исключает автоматическое создание дополнительной Machine при первой поставке. Поддерживайте ровно один экземпляр: SQLite находится на локальном томе, репликации между Machines нет. Автоматическая остановка выключена, HTTPS включён. Fly выставляет счёт за используемые ресурсы по условиям аккаунта.

База хранится в `/data/klassno/klassno.sqlite` на постоянном томе. Root filesystem Machine и `/tmp` временные и могут очищаться при перезапуске; не храните там базу или единственные резервные копии. При старте `docker/entrypoint.sh` кратковременно работает от root: создаёт `/data/klassno` с владельцем `node` и правами 700, задаёт права 600 и владельца `node` существующим файлам БД/WAL/SHM, отклоняет symlink для каталога и этих файлов, затем запускает сервер через `gosu node:node`. Корень тома и чужие файлы не меняются. Сервер работает без root. Health endpoint `/api/health` проверяет доступность соединения SQLite и отдаёт только `{"status":"ok"}` без аккаунтов и сессий.

Последующие обновления: `flyctl deploy --remote-only --ha=false`; после обновления проверьте health, вход и сохранённые классы. Для диагностики используйте `flyctl logs` и `flyctl checks list`. Первому учителю нужно самостоятельно зарегистрироваться на сайте; предустановленных логинов нет. Адрес уже включён в ALLOWED_ORIGINS вместе с двумя native origins. При смене домена одновременно обновите PUBLIC_URL и ALLOWED_ORIGINS.

Одноразовое восстановление пароля на текущей Machine:

```sh
flyctl ssh console -C 'gosu node:node npm run reset-password -- USER_LOGIN'
```

Сначала проверьте личность владельца; вывод содержит секретную ссылку, которую нужно передать лично. Для резервирования используйте snapshots тома и отдельные резервные копии; наличие одного тома не обеспечивает отказоустойчивость. Не удаляйте Machine/том ради обновления и не масштабируйте сервер до нескольких экземпляров без пересмотра хранения.

Для мобильной сборки с публичным API:

```sh
VITE_API_URL=https://klassno-school-ayudenko.fly.dev \
VITE_WEB_URL=https://klassno-school-ayudenko.fly.dev npm run mobile:sync
```

Настройки основаны на [справочнике Fly configuration](https://fly.io/docs/reference/configuration/) и [описании Fly Volumes](https://fly.io/docs/volumes/overview/).
