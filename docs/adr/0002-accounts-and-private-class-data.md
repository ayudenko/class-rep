# ADR 0002 — Общий сервер, собственные аккаунты и границы доступа

## Контекст

Пользователь выбрал реальные аккаунты: email и пароль для взрослых, логины учеников от учителя, персональные приглашения родителей к ребёнку. Приложение хранит анкеты несовершеннолетних и должно разделять доступ семей и классов. Основание: спецификация, подтверждённые решения брифинга, «Реализация», G02/G03, R02.1/R04.1/R12i; соответствующие требования манифеста.

## Решение

Использовать один Node/Express сервер и файловую SQLite с постоянным томом, без обязательного внешнего облачного аккаунта. Первое развёртывание — один экземпляр сервера. Учитель управляет своим классом; ученик видит себя, родитель — связанного ребёнка. Принадлежность проверяется сервером, приватная заметка выдаётся только учителю. Анкета содержит только оговорённые минимальные данные.

Пароли хранятся в виде хешей; приглашения одноразовые и ограничены по сроку. Веб-сессия использует HttpOnly cookie, мобильная — bearer в памяти. Сессии ограничены по сроку и отзываются при выходе/смене пароля. Восстановление выполняется через оператора после проверки личности.

## Почему

Такое размещение обеспечивает локальную работу с настоящими аккаунтами без зависимости от платного облака. Обязательный внешний сервис идентификации не нужен для подтверждённых способов входа. Хранение только в браузере не обеспечивает общий класс, серверное разграничение доступа и сохранность аккаунтов после перезапуска. Проверки ролей только в интерфейсе не защищают от подстановки чужих идентификаторов. Токены в localStorage отклонены в пользу предусмотренного минимального хранения в памяти; secure storage можно добавить позднее. Имитация восстановления по email отклонена, поскольку SMTP не подключён.

## Последствия

Оператор отвечает за постоянный том, резервирование, HTTPS и настройку разрешённых origins. Для нескольких экземпляров сервера потребуется пересмотреть выбранное размещение базы. После закрытия мобильного приложения нужен повторный вход. Родитель получает доступ через приглашение, а не самостоятельный выбор произвольного ребёнка. Адреса, медицинские данные и публичные рейтинги детей не входят в сбор данных.
